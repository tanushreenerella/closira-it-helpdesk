# ML results

Generated by the scripts in `backend/ml/`. The multi-task DistilBERT
(`distilbert-base-uncased`, shared encoder + intent/emotion heads) was trained on Colab
(T4, best epoch 3 of 5, early stopping) — the model itself is not in git.

| File | Produced by |
|---|---|
| `data_stats.json` | `data.build_datasets` (Colab run — the splits the models were scored on) |
| `abcd_stats.json` | `data.build_abcd` |
| `multitask.json` | `multitask` — DistilBERT training history + test-split macro-F1 / per-class F1 |
| `baselines.json`, `baselines_per_class_f1.csv` | `baselines` (Colab run, same splits as `multitask.json`) |
| `ood_multitask.json`, `ood_tfidf_logreg.json` | `evaluate_ood` — all 616 legacy IT messages, current router |
| `calibration_multitask.json`, `calibration_tfidf_logreg.json` | `calibrate` — 50/50 split, grid search, operating points |
| `thresholds_selected.json` | the thresholds set in `router.py`, scored for both models |
| `accuracy.json` | `accuracy` — DistilBERT accuracy + macro-F1 with majority-class baselines |

## In-domain test split (macro-F1)

Both models on the same Colab test split.

| Task | Keyword rules | TF-IDF + LogReg | DistilBERT multi-task |
|---|---|---|---|
| Intent (7 classes, 4,983 rows) | 0.602 | 0.965 | **0.982** |
| Emotion (6 classes, 3,998 rows) | 0.403 | 0.541 | **0.572** |

Per-class F1, TF-IDF → DistilBERT. Intent: information_request 0.96→0.97, issue_report
0.94→0.97, action_request 0.95→0.97, complaint 0.99→1.00, feedback 0.98→0.99,
appreciation 0.99→0.99, chit_chat 0.95→0.98. Emotion: angry 0.47→0.51, frustrated
0.37→0.43, confused 0.39→0.43, sad 0.58→0.60, happy 0.76→0.80, neutral 0.66→0.66.

**Caveats.** complaint / feedback / appreciation labels come from TWCS keyword rules, so
in-domain F1 for them overstates real performance until `data/review/twcs_review_200.csv`
is hand-checked; other intents are partly separated by source domain. Emotion
(GoEmotions, Reddit) remains the hard task.

### Accuracy with majority-class baselines (DistilBERT, `accuracy.json`)

| Evaluation set | Rows | Accuracy | Macro-F1 | Majority-class accuracy |
|---|---|---|---|---|
| Intent — test split | 4,983 | **0.977** | 0.982 | 0.341 (information_request) |
| Emotion — test split (training distribution) | 3,998 | **0.663** | 0.572 | 0.396 (neutral) |
| Emotion — GoEmotions official test, natural distribution | 401 | **0.633** | 0.514 | 0.402 (happy) |

- The test splits are the ones the model was trained against (macro-F1 matches
  `multitask.json`).
- The training build's neutral-downsampling rule never triggered (16,021 neutral vs a cap
  of 31,388), so the emotion test split already has the natural single-label distribution.
- The natural-distribution set is GoEmotions' official test file (single-label, same
  mapping, no downsampling). 3,681 of its 4,590 single-label texts also appear in our
  train/val split — the build pooled all of GoEmotions before re-splitting — so they are
  removed to avoid leakage, leaving 401 rows (only 4 `confused`); its macro-F1 is noisy.
- Accuracy reads well above macro-F1 for emotion because `happy` and `neutral` dominate;
  compare it with the majority-class column, not with 0.

## Escalation on the 616 legacy IT-helpdesk messages

Gold = legacy label != `normal` (462 of 616 should escalate). Router = what the pipeline
does in the FAQ stage (keyword hard overrides + model risk).

**Caveat — synthetic data.** The 616 messages were generated with an LLM
(`legacy/nlp/generate_dataset.py`), not collected from real employees, and the new
keyword phrases were mined from the same set (its calibration half). Held-out numbers
are therefore in-distribution for both the phrasing and the keywords: expect lower
recall on real helpdesk traffic, where people phrase human requests and repeated
failures in ways this generator didn't. Treat these as a regression benchmark, not an
estimate of production performance.

**Method.** There is no other IT-domain escalation-labelled data, so the 616 messages
are split 50/50 stratified by legacy label (seed 42, `calibrate.py`). The keyword-list
expansion and the threshold search used **only the calibration half**; the held-out
half (308 messages: 231 escalate, 77 normal) was not looked at until scoring. Each
half has only 77 normal messages, so one false alarm = 1.3 points of false-alarm rate.

### Held-out half — before / after

| Step | Model | Precision | Recall | F1 | False alarms |
|---|---|---|---|---|---|
| Old keywords, thresholds intent 0.5 / risk 0.75 / complaint 0.5 | TF-IDF | 0.944 | 0.437 | 0.598 | 0.078 |
| | DistilBERT | 0.982 | 0.468 | 0.633 | 0.026 |
| **Expanded keywords, same thresholds (current)** | TF-IDF | 0.946 | 0.762 | 0.844 | 0.130 |
| | **DistilBERT** | **0.969** | **0.801** | **0.877** | **0.078** |

Held-out recall by legacy label, current router:

| | explicit_human_request | frustrated | repeated_confusion | normal (false alarm) |
|---|---|---|---|---|
| TF-IDF | 0.935 | 0.623 | 0.727 | 0.130 |
| DistilBERT | 0.935 | 0.753 | 0.714 | 0.078 |

**Threshold choice.** The thresholds stay at intent 0.5 / risk 0.75 / complaint 0.5
(`router.py`, pinned by `test_routing_thresholds_are_the_chosen_operating_point`). The
best-recall point within a 10% calibration-half false-alarm budget (intent 0.4 / risk
0.55) was tried and rejected: its false alarms rose to 16.9% on the held-out half
(13 of 77 normal messages vs 5 of 77 on the calibration half). Operating points for
DistilBERT, held-out half (`calibration_multitask.json`):

| Operating point | Thresholds (intent / risk / complaint) | Held-out P | R | F1 | False alarms |
|---|---|---|---|---|---|
| **current** | 0.5 / 0.75 / 0.5 | 0.969 | 0.801 | 0.877 | 0.078 |
| <= 5% calibration false alarms | 0.4 / 0.60 / 0.5 | 0.960 | 0.823 | 0.886 | 0.104 |
| <= 10% | 0.4 / 0.55 / 0.5 | 0.940 | 0.875 | 0.906 | 0.169 |
| <= 20% | 0.4 / 0.525 / 0.5 | 0.917 | 0.905 | 0.911 | 0.247 |
| ~80% recall target | 0.8 / 0.40 / 0.5 | 0.841 | 0.827 | 0.834 | 0.468 |

These were chosen for DistilBERT; the TF-IDF fallback runs with the same values.

**Where the gain came from.** Almost all of it is the keyword expansion: explicit human
requests went from ~0.6 to ~0.94 held-out recall, repeated confusion from ~0.05 to
~0.71. Part of that is a bug fix — the 616 messages use curly apostrophes ("doesn’t"),
which the keyword lists never matched. DistilBERT adds most on `frustrated` (0.75 vs
0.62) and halves TF-IDF's false alarms.

**Cross-domain check (ABCD validation turns, retail chat, rule-derived labels, ~1%
positive; not used for selection):** DistilBERT P 0.25 / R 0.46 at the current
thresholds (`calibration_*.json`). Its labels come from different keyword rules, so treat
it only as a sign of how much the router over- or under-escalates outside IT support.
